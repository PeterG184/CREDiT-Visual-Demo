# CREDiT Digital Twin Platform — Technical & Design Specification

---

## 1. Executive Summary & System Overview

The **CREDiT Digital Twin Platform** is an interactive monitoring, forecasting, and load management interface designed for a rural community solar microgrid in Sub-Saharan Africa. The system bridges physical microgrid infrastructure with human-centric decision-making, providing real-time operational visibility, predictive load guidance, and streamlined maintenance reporting.

### Microgrid Physical Topology & Hardware Specifications

```
                       [ 50.3 kWp PV Array ]
                    (86 x 585W Panels / Multi-String)
                                |
               +----------------+----------------+
               |                                 |
     [ Solis S5-GR3P17K ]              [ Solis S5-GR3P17K ]
   (17 kWac / 25.5 kWdc)             (17 kWac / 25.5 kWdc)
               |                                 |
               +----------------+----------------+
                                | (AC Bus)
                                |
                [ Sunsynk SUN-20K-SG05LP3-EU-SM2 ]
                      (20 kWac Battery Inverter)
                                |
            +-------------------+-------------------+
            | (48V DC Bus)                          |
   [ Tower 1: 10 x Dyness DL5.0C ]         [ Tower 2: 10 x Dyness DL5.0C ]
     (51.2 kWh / 51.2V Stack)                (51.2 kWh / 51.2V Stack)
            \                                       /
             +------------------+------------------+
                                |
                   Total Storage: 102.4 kWh

```

* **Photovoltaic (PV) Generation:** 50.3 kWp total capacity across 86 monocrystalline 585W panels wired into multiple strings with per-string Voltage ($V$) and Current ($I$) sensing.
* **PV Inverters:** 2 x Solis S5-GR3P17K 3-Phase inverters operating in parallel (34 kWac rated output, 51 kWdc max input).
* **Battery Storage Inverter:** 1 x Sunsynk/Deye SUN-20K-SG05LP3-EU-SM2 (20 kWac continuous rating with bidirectional AC/DC coupling).
* **Energy Storage System (ESS):** 102.4 kWh total gross storage configured as two parallel vertical towers. Each tower contains 10 x Dyness DL5.0C Pro modules (5.12 kWh, 51.2V, 100Ah each).
* **Environmental Monitoring Station:** Integrated weather station reporting ambient temperature (°C), relative humidity (%), global horizontal solar irradiance ($W/m^2$), wind speed ($m/s$), and wind direction (degrees/cardinal).

### Stack Decisions & Constraints

* **Frontend Framework:** React Native with React Native Web (TypeScript). Enables a single codebase for Android/iOS deployment and the browser interface.
* **State Management:** React Context API or lightweight Zustand store for reactive client state.
* **Backend Runtime:** Node.js with Express / Fastify written in TypeScript.
* **Web Server / Reverse Proxy:** Nginx handling port 80/443 traffic, caching static bundles, and routing `/api/v1/*` upstream to the Node.js process running on `localhost:5000`.
* **Data Tier Evolution:** Phase 1 uses an in-memory dynamic state simulator. Phase 2 binds the same REST endpoints to PostgreSQL without requiring frontend refactoring.

## 3. UI/UX Design System & Global Guidelines

### Tone and Accessibility Principles

* **Tone:** "Neutral-Happy" — grounded, clear, warm, and reassuring. Avoid technical alarmism.
* **Descriptive Primacy:** Metric cards present actionable text descriptors alongside clean values rather than complex multi-line graphs.
* **Single-Variable Visualizations:** Graphs display strictly one data stream per view (e.g., only solar generation over time, never solar vs. load vs. irradiance stacked on one axis).
* **Sunlight Readability:** High-contrast text on solid backgrounds. Minimum contrast ratio of 4.5:1 for normal text, 3:1 for large graphical elements.
* **Internationalization (i18n):** All visible UI text must be referenced via structured key lookup (e.g., `t('dashboard.battery.status')`). No hardcoded English strings in JSX.

#### Diagnostic Leeway Logic (Expected vs. Actual)

* **Calculation:**

$$\Delta P = \frac{P_{\text{expected}} - P_{\text{actual}}}{P_{\text{expected}}}$$


* **Rule Engine:**
* $\Delta P \le 15\%$: **Green (Optimal)** — normal variance from atmospheric scatter, dust, and temperature coefficients.
* $15\% < \Delta P \le 30\%$: **Yellow (Minor Variance)** — flagged for cleaning or inspection.
* $\Delta P > 30\%$ OR Hardware Alarm Bit Active: **Red (Fault Condition)** — triggers urgent diagnostic alert.



#### Dynamic Form Validation & Field Rules

* **Technician Name:** Plain text string (Min 3 characters, required).
* **Incident Date:** Date-time picker, defaults to client device timestamp, allows past manual dates.
* **Equipment Checkbox Group:** Single or multi-selection.
* **Dynamic Fault Checkboxes:** Mutates options depending on the equipment selected:
* *Solis Inverters:* `DC Isolation Fault`, `Grid Overvoltage`, `Inverter Over-temperature`, `String Disconnect`.
* *PV Panels Array:* `Physical Glass Damage`, `Severe Soiling / Dust`, `Vegetation Shading`, `Connector Corrosion`.
* *Dyness Battery Towers:* `Cell Imbalance`, `High Internal Temp (>45°C)`, `BMS Communication Timeout`, `Short Circuit Protection`.
* *Weather Station:* `Anemometer Jammed`, `Pyranometer Soiled`, `Sensor Disconnected`.


* **Photo Upload:** Accepts JPEG/PNG/WebP, up to 5 MB, compressed client-side before transmission.
* **Auto-Computed Urgency:**
* `HIGH`: Dyness BMS alarms, Sunsynk inverter lockout, or Water Pumping system impacted.
* `MEDIUM`: Solis Inverter performance variance $> 20\%$, individual string disconnects.
* `LOW`: Dust soiling, non-critical sensor timeouts, cosmetic damage.

## 5. Dynamic Mock Data & Simulation Engine

The backend implements a lightweight physics simulation module that runs continuously. When an API client requests data, the simulator returns values computed from the real server clock time.

```
+---------------------------------------------------------------+
|                    SERVER TIME CLOCK (UTC)                    |
+---------------------------------------------------------------+
                               |
                               v
+---------------------------------------------------------------+
|                   DIURNAL SOLAR MODEL                         |
|   - Inputs: Hour of Day (0-24), Solar Zenith Angle            |
|   - Equation: Half-sine curve from 06:00 to 18:00             |
|   - Multiplier: Dynamic Cloud Noise factor (0.75 - 1.05)      |
|   - Yield: Max 50.3 kWp DC -> Split across 2 Solis Inverters  |
+---------------------------------------------------------------+
                               |
                               v
+---------------------------------------------------------------+
|                   ALLOCATION & LOAD DEMAND                    |
|   - Sums active loads based on current time slot:             |
|     * Water (9kW), Workshop (10kW), Bakery (9kW),             |
|       Mill (10kW), Continuous Services (14kW)                 |
+---------------------------------------------------------------+
                               |
                               v
+---------------------------------------------------------------+
|                   BATTERY BALANCING ENGINE                    |
|   - Net Power = Total Solar Generated - Total Load Demanded   |
|   - If Net > 0: Charge Dyness Towers (Max 20 kW rate)         |
|   - If Net < 0: Discharge Dyness Towers (Max 20 kW rate)      |
|   - Integrates kWh state across simulated hourly timesteps    |
+---------------------------------------------------------------+

```

### Mathematical Simulation Rules

#### 1. Solar Generation Curve

For hour $t \in [6.0, 18.0]$:


$$P_{\text{ideal}}(t) = P_{\text{peak}} \times \sin\left(\pi \times \frac{t - 6}{12}\right)$$


Where $P_{\text{peak}} = 50.3 \text{ kW}$. For $t < 6$ or $t > 18$, $P_{\text{ideal}}(t) = 0$.

#### 2. Atmospheric & Temperature Degradation

$$P_{\text{actual}}(t) = P_{\text{ideal}}(t) \times \eta_{\text{inverter}} \times (1 - \gamma (T_{\text{ambient}} - 25)) \times \text{Noise}(t)$$


Where:

* $\eta_{\text{inverter}} = 0.98$ (98% Solis efficiency)
* $\gamma = 0.0035 / ^\circ\text{C}$ (PV temperature derating coefficient)
* $T_{\text{ambient}} = 22 + 10 \times \sin\left(\pi \times \frac{t - 8}{12}\right)$
* $\text{Noise}(t) \in [0.92, 1.02]$ (stochastic micro-fluctuation)

#### 3. Battery State of Charge ($SoC$) Integration

$$\Delta E = (P_{\text{generation}} - P_{\text{load}}) \times \Delta t \times \eta_{\text{battery}}$$

* If charging ($P_{\text{gen}} > P_{\text{load}}$), $\eta_{\text{battery}} = 0.95$ (charging efficiency).
* If discharging ($P_{\text{gen}} < P_{\text{load}}$), $\eta_{\text{battery}} = 1.05$ (round-trip discharge loss factor).
* Absolute bounds: $SoC \in [10\%, 100\%]$ to reflect Dyness BMS protective depth-of-discharge cutoffs.

## 7. Infrastructure, Hosting & Deployment Configuration

### AWS Lightsail Architecture Setup

The platform runs on an AWS Lightsail Ubuntu 24.04 LTS instance (2 GB RAM, 1 vCPU, 60 GB SSD) behind an Nginx reverse proxy.

```
 Internet (Port 80/443)
           |
           v
 +-------------------+
 |   Nginx Router    |
 +-------------------+
    |             |
    | /           | /api/v1/*
    v             v
 Static Web    Node.js / Express Server
 Bundle        (localhost:5000, PM2 Cluster)

```

### Nginx Server Configuration (`/etc/nginx/sites-available/credit-twin`)

```nginx
server {
    listen 80;
    server_name credit-twin.community.local;

    # Redirect all plain HTTP to HTTPS
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name credit-twin.community.local;

    ssl_certificate /etc/letsencrypt/live/credit-twin.community.local/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/credit-twin.community.local/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;

    # Root folder for compiled React Native Web static distribution
    root /var/www/credit-twin/frontend/dist;
    index index.html;

    # Client-side routing fallback for React Single Page Application
    location / {
        try_files $uri $uri/ /index.html;
        add_header Cache-Control "no-cache";
    }

    # Reverse proxy upstream to TypeScript Node.js backend
    location /api/v1/ {
        proxy_pass http://127.0.0.1:5000/api/v1/;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;

        # Upload limits for fault photo submissions
        client_max_body_size 10M;
    }

    # Static assets caching rule
    location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|woff|woff2)$ {
        expires 30d;
        add_header Cache-Control "public, no-transform";
    }
}

```

### Developer Acceptance Criteria

* **Responsive Viewport Integrity:** Layouts must render without horizontal scrollbars across all screen widths from 360px (mobile) up to 1024px (desktop shell).
* **Time-Synchronized Dynamic Telemetry:** Opening the webapp at 13:00 must show high solar generation (~30–45 kW) and active afternoon operations; opening the webapp at 21:00 must show 0 kW solar generation, discharging batteries, and active residential lighting.
* **Single-Variable Chart Compliance:** The 24-hour forecast view must render only generation kW against time. No secondary axes or overlapping metrics may be added to the chart canvas.
* **Schedule State Toggle:** The Energy Allocation screen must cleanly toggle between the standard 235 kWh baseline schedule and today's dynamically shifted schedule without page reloads.
* **Diagnostic Fault Filtering:** On the maintenance screen, selecting an equipment item (e.g., "Solis Inverters") must restrict the fault options strictly to inverter-relevant diagnostic codes.
* **Leeway Calculation:** Equipment output variances between 0% and 15% must retain a green status; variances between 15% and 30% must display yellow without sounding false alarm states.
* **i18n Readiness:** 100% of display strings must reside in a structured JSON translation catalog (e.g., `locales/en.json`) to allow immediate drop-in replacement with local language dictionaries in Phase 2.
